# D455 使用与 YOLO 部署现状（2026-08-02）

详细的 Docker 节点接口、容器依赖和验证记录见 [Docker_Yolo_Combine_0720.md](Docker_Yolo_Combine_0720.md)。本文只说明整机的数据所有权和当前部署边界。

## D455 唯一所有权

D455 只能由 Docker 内的一个 RealSense ROS 节点打开。该节点同时向 Docker 内部提供：

```text
IR1 + IR2 + IMU       -> cuVSLAM
RGB 640x360 @ 30 Hz   -> D455 YOLO 3D
Raw Depth @ 60 Hz     -> D455 YOLO 3D 和后续几何避障
```

Host 侧不得启动 `pyrealsense2.pipeline.start()`、第二个 `realsense2_camera`、旧 Host YOLO 节点的直接相机模式，或任何其他直接访问 D455 的程序。

## 当前 YOLO 3D 链路

```text
Docker RealSense
  -> RGB + Raw Depth + 两路 CameraInfo + RealSense TF
  -> /d455_object_yolo_3d
  -> YOLOv8-seg + 低频稀疏 depth-to-color 投影
  -> camera_link XYZ
  -> UDP 127.0.0.1:19002
```

节点使用现有 `best.pt` 的三类：`red`、`green`、`obstacle`。当前仍使用 Ultralytics `.pt` 和 PyTorch，TensorRT engine 是后续独立的性能优化工作，尚未作为运行前提。

不使用 `/camera/aligned_depth_to_color/image_raw`。为了控制 Xavier NX CPU 负载，RealSense 保持 `align_depth.enable=false`；YOLO 节点只在自身 5 FPS 工作周期里，从 Raw Depth 反投影、变换到 Color 平面，再用 segmentation mask 筛选并求稳健中位值。

## 当前与后续的职责

| 模块 | 当前状态 |
|---|---|
| Docker RealSense | 已有可用节点，本轮不修改 |
| Docker cuVSLAM | 已有可用节点，本轮不修改 |
| Docker `/d455_object_yolo_3d` | 已实现并完成基础真机链路验证 |
| UDP `19002` | 已实现，输出 `camera_link` JSON v1 |
| Host detection bridge | 尚未实现 |
| `/yolo/detections`、`/block/target_pose`、`/cone/detections` | 等 Host bridge 实现后发布 |
| `base_link` 坐标转换 | 等相机安装外参与 Host bridge |
| PointCloud2 / Nav2 VoxelLayer | 尚未接入，独立于 YOLO 安全链路 |

Host bridge 完成后才负责将 `camera_link` 点转换为 `base_link`，TaskManager 和机械臂不应直接消费现阶段的 UDP 数据。

## 已完成验证

- D455 同时输出 RGB `640x360 @ 30 Hz` 和 Raw Depth `640x360 Z16 @ 60 Hz`；
- `enable_sync=false`、`align_depth.enable=false`、IR emitter off；
- Docker 内 RealSense 与 YOLO 同容器 ROS 通信可用；
- 推理约 75-189 ms，通常 RGB-Depth 时间差 0.4-8 ms；
- 4 秒内发送 20 个 UDP 包，约 5 FPS；
- 空检测健康包的 `frame_id` 为 `camera_link`。

尚未用被模型识别的、已知距离目标验证真实 XYZ 误差。下一次测试需在 D455 前放置红色/绿色目标或锥桶，并对比卷尺距离、横向方向和重复测量稳定性。

## 部署与协作原则

验证镜像基于 `cuvslam_yolo:humble`，运行时需只读挂载 Jetson 已验证的 Host Torch/Ultralytics site-packages 和 CUDA 库。不要在 Jetson 原仓库直接覆盖同事的改动：用本功能的 Git commit/patch 在独立 worktree 或 `/tmp` 构建上下文测试，验证后再由合并负责人 cherry-pick。
